# 舰装格局

本项目使用 **OpenAI Codex** 编写。

这是一个用于 EVE Frontier 的飞船配装工具。你可以在网页里画出飞船的可用空间和装备形状，拖拽装备进行手动配装；也可以设置必装装备和数量限制，用 **CP-SAT 算法自动求解优质配装方案**。配装方案支持保存、导入和导出。

当前稳定版本：**v1.2.1（2026-10-08）**。用户可见变化见 [CHANGELOG.md](CHANGELOG.md)，运行维护与后续集成说明见 [docs/PROJECT_HANDOFF.md](docs/PROJECT_HANDOFF.md)，其他资料可从 [文档导航](docs/README.md) 进入。

自动求解在使用者自己的电脑上运行，不需要购买服务器。

## 本地运行

### Windows 安装包（推荐）

在 [GitHub Releases](https://github.com/donlan96/evefrontier-fitter/releases/latest) 下载 `EveFrontierFitter-1.2.1-Setup-x64.exe`，安装后双击桌面的“舰装格局”快捷方式。程序会自动在浏览器打开 `http://localhost:3000`。

v1.2.0 安装包存在缺少 React 运行依赖的已知问题，请使用 v1.2.1 或更新版本。已安装旧版时直接覆盖安装，个人存档保留。

安装包自带 Node.js、Python 和 CP-SAT，无需另装运行环境，安装后可离线使用。默认内置“掠夺者”（294 格）、“初始飞船”（478 格）两个棋盘和 23 个装备定义；首次使用无需重新绘制，选择棋盘后创建自己的命名配装即可。

开始菜单中的“停止舰装格局”可停止后台服务。个人数据保存在 `%LOCALAPPDATA%\EveFrontierFitter\data`，升级和卸载均保留；已有用户数据不会被默认棋盘或装备覆盖。旧源码版还在运行时，请先用它的停止入口关闭服务，再打开安装版。

### 从源码运行（开发者）

当前日常启动器面向 Windows。首次使用需安装 [Node.js](https://nodejs.org/) 22.13 或更新版本、[Python](https://www.python.org/downloads/) 3.11 或更新版本，并确保 Python 能通过 `python` 命令运行。

在 PowerShell 中执行以下命令获取源码和前端依赖（Git 已安装时）：

```powershell
git clone https://github.com/donlan96/evefrontier-fitter.git
cd evefrontier-fitter
npm install --global pnpm@11.17.0
pnpm install --frozen-lockfile
pnpm run build
```

也可以在 GitHub 点击 **Code → Download ZIP**，解压后在项目目录执行后面三条命令。首次启动会自动创建 Python 虚拟环境并安装后端依赖，需要联网；之后可在本机运行。

准备完成后，日常使用直接双击：

```text
启动配装工具.bat
```

启动器会在后台运行本地网页和 CP-SAT 求解器，等待服务就绪后自动打开 `http://localhost:3000`，不会留下命令提示符窗口。使用完毕后双击 `停止配装工具.bat`。后台日志位于 `%LOCALAPPDATA%\EveFrontierFitter\logs`。

`start-dev.bat` 仅用于开发调试，会显示实时日志窗口并启用热更新。详细手动命令及健康检查见 `backend/README.md`。

仅启动前端时可使用：

```bash
pnpm install
pnpm run dev
```

打开开发服务器输出的本地地址。生产构建使用：

```bash
pnpm run build
```

## 当前功能

- 点击或拖动编辑飞船有效格；
- 棋盘尺寸先输入草稿，再点击“应用尺寸”，避免输入过程中误触发缩放；
- 自动保留最近 20 份棋盘修改前快照，并连同当时配装和锁定状态一起恢复；
- 棋盘必须先在棋盘编辑页创建和保存；配装工作台只负责从左侧选择已有棋盘，切换后只显示该棋盘的命名配装；
- 绘制并编辑自定义装备模块；
- 从模块库拖入棋盘或移动已放置模块；
- 拖动时用滚轮按 90° 旋转；
- 实时显示越界、无效格和重叠冲突；
- 非法松手时取消放置或恢复原位；
- 选中模块后旋转、删除或清空配装；
- 同色模块使用跨越网格间距的连续深色外轮廓区分，内部格线保持较淡；
- 显示空间利用率、剩余格、模块数和基础评分。
- 将棋盘、模块定义和配装结果导入或导出为带版本号的纯 JSON。
- 通过本机 FastAPI 服务把棋盘库、模块、配装、历史、最优证明、当前工作区和上次结果自动保存到 `%LOCALAPPDATA%\EveFrontierFitter\data\fitter-data.json`；写入采用递增 revision、原子替换，并保留上一份有效自动备份。
- 首次读取本机存档失败时工作区保持只读，只能重新读取，成功恢复完整磁盘基线后才允许编辑与自动保存。已读取后的网络保存失败保留内存修改和相同 revision 供重试；多页面 revision 冲突停止旧请求并要求确认后重新载入。全程不回退浏览器存储，也不会误报保存成功。旧浏览器 LocalStorage 数据不迁移、不删除。
- 每块棋盘拥有自己的命名配装列表；配装需要先通过独立入口输入名称和说明创建，随后才能手动搭配或自动求解。
- 当前配装只提供“保存修改、编辑名称与说明、删除配装”；不提供标签、另存为或未命名草稿，创建入口与当前配装管理区分离。
- 配装工作台与自动配装共享同一个当前档案；计算并应用方案后可切回工作台检查，再明确保存修改。
- 命名配装只在点击“保存当前”时更新，自动计算和手动调整只标记为未保存修改，不会悄悄覆盖已保存版本。

`ShipFitterApp` 通过 TypeScript 属性接收初始棋盘、模块和摆放数据，并可通过 `onDocumentChange` 向宿主页面回传完整文档。`enableLocalPersistence={false}` 可以关闭组件内本地存档，但当前装配与求解入口仍要求已保存棋盘和命名配装；关闭持久化后无法满足该前提，因此此模式尚不能作为完整宿主配装流程使用。`src/index.ts` 是组件入口，`src/core/index.ts` 是无 React 依赖的核心入口。示例数据只在独立页面入口中注入。

## 自动配装

- 自动配装全部由本机 Google OR-Tools CP-SAT 服务完成，不保留旧回溯或随机启发式模式；
- 每种模块可设置必装数量、是否参与和最大数量；
- 支持空棋盘、保留当前摆放，以及锁定部分模块后重排其他模块；
- 严格满足全部必备和锁定约束后，仅最大化模块总评分；利用率和剩余格只作为结果统计；
- “重排未锁定模块”只固定明确锁定的实例，其他模块的位置和数量都允许重新选择；
- 提供 30 秒、1 分钟、5 分钟、15 分钟及不限时模式；
- 计算时显示已运行时间、当前最佳评分、CP-SAT best objective bound、差距和最优性证明状态；
- 手动停止会请求 CP-SAT 终止搜索，并保留、展示和保存停止前的完整最佳方案；
- 本机永久保留每次求解诊断，服务重启后仍可检查候选规模、上界变化与停止时的 CP-SAT 统计；
- 按“棋盘 ID + 排序后的必备模块及数量 + 锁定模块布局”识别配装型号；
- 每个型号在本机文件存档中保留当前评分下的前五个不同布局，支持应用、删除和清空；
- 历史方案读取与结果应用时检查模块删除、形状、旋转、边界、重叠、库存、必备数量、候选启用/最大数量和固定布局；旧记录原样保留，失效方案不参与当前最佳；
- 相同型号开始计算时验证当前手动布局和历史第一名，将较优者作为 CP-SAT hint 与初始最佳，较差的新计算不会覆盖旧记录；
- 没有合法完整布局 hint 和锁定模块时，可从两份兼容的其他严格最优历史中按规范化形状生成恰好两条大型零分必备模块正 hint；不满足严格条件就完全回退，不写死模块或坐标；
- 上次求解结果会保存在本机并跨页面模式、刷新和重新打开保留，直至下一次计算完成后替换；
- 方案按排名直接应用；若棋盘或模块已改动导致旧方案失效，应用前会拦截并提示重新计算；
- 前端通过 `src/services/solverApi.ts` 访问只监听本机的 FastAPI 服务；Python 请求模型与 React 类型相互独立。

镜像操作暂未启用。

模块基础评分必须为非负有限数，最多三位小数；导入、编辑和后端使用相同边界，方案评分按千分整数累计。最优证明还要求 CP-SAT 的原始整数目标与原始上界严格相等，界面显示值相等不构成证明。
